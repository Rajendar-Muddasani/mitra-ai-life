Project 01 · Live Public Kit

Document Q&A Assistant

This is the first public kit in the thesis-ready Projects track. A student builds a document question-answer system that can ingest files, retrieve relevant chunks, answer with citations, and demonstrate both technical depth and real-world usefulness.

Ask for kit access See deliverables

Who this fits

  • Third-year mini-project teams
  • Final-year major project submissions
  • Students who need a viva-friendly AI system, not a toy demo
  • Freshers who want one strong RAG system on GitHub
What gets built

System outcome

Upload flow

PDF, DOCX, or text documents are uploaded and prepared for retrieval.

Retrieval pipeline

Chunking, embeddings, vector search, reranking, and answer synthesis with citations.

Presentation-ready demo

Clean interface, sample dataset, architecture diagram, and viva explanation path.

Stack

Recommended stack

Core build

Python, FastAPI, LangChain or direct pipeline, ChromaDB or pgvector, OpenAI embeddings or multilingual embeddings, and a simple frontend.

Deployment options

Streamlit Cloud for simplest demo, Render or Railway for API deployment, Vercel for frontend, and optional Docker for repeatable setup.

Timeline

Major project plan

Weeks 1-2

Problem statement, dataset/document source selection, upload rules, baseline architecture.

Weeks 3-4

Document parsing, chunking strategy, embedding selection, storage pipeline.

Weeks 5-6

Retrieval, prompt construction, citation formatting, error handling.

Weeks 7-8

Frontend polish, example prompts, admin flow, and evaluation cases.

Weeks 9-10

Report writing, PPT build, viva questions, and deployment proof.

Extension path

Role-based access, multilingual Q&A, feedback loop, analytics, and domain tuning.

Included

What a serious kit must contain

Build pack

Architecture, milestones, file structure, starter code, and final code path.

Submission pack

Report template, PPT template, screenshots, limitations section, and evaluation checklist.

Viva pack

Expected questions, short answers, technical deep-dive answers, and fallback explanations.

Portfolio pack

README structure, GitHub presentation, demo script, and placement talking points.

Deployment pack

Streamlit or frontend deployment, API hosting, environment setup, and recovery checklist.

Extension ideas

Multilingual support, organization-specific knowledge base, analytics dashboard, and access controls.

Why this is a strong first kit

Why it works for thesis and hiring

  • It is useful to colleges, offices, hospitals, and internal teams.
  • It demonstrates modern AI concepts without needing giant hardware.
  • It naturally supports architecture explanation, evaluation, limitations, and deployment discussion.
  • It produces one project that is strong for report submission and for GitHub portfolio signaling.
Guardrail

Academic honesty position

This kit is for learning, building, explaining, and presenting your own work. It is not positioned as “pay and get a fake submission.” The value is in guided structure, working code, deployment support, and the ability to defend the project properly in viva and interviews.
